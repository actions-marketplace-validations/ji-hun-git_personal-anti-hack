# What the numbers can and cannot rule out

Generated by [`bench/stats.py`](../bench/stats.py) from `bench/results/2026-11-18-rules.json`, `bench/results/2026-11-11-models.json`, `bench/results/2026-11-18-drill.json`, `bench/results/2026-11-18-chains.json`, `bench/results/2026-11-18-fuzz.json`, `bench/results/2026-11-18-real-repos.json`, `bench/results/2026-11-18-independent.json`, `bench/results/2026-11-18-shellgate.json`. Rerun it after any benchmark.

Every rate below comes with an **exact 95% confidence interval** (Clopper-Pearson): the range of true rates that would make the observed count unsurprising. When a count is 0 or all of the cases, the interval still has width, and that width is the honest answer to "how sure are we": 76 of 76 caught means the true rate is at least 95.3%, not 100%. Comparisons on the same cases use the **exact McNemar test**, which looks only at the cases where the two disagree.

**What the intervals assume.** They treat each case as an independent draw. TrapRepo's cases were written to cover techniques from real incidents, not sampled at random from all attacks, so read an interval as what this corpus can rule out, not as a rate for every attack in the wild. The popular repositories are a sample of 30 chosen by hand, not drawn at random either.

**What the rules have seen.** Whenever a case got through, the rules were fixed until it did not: four of the cases added in 0.4.0 needed new detection, and the fuzzer's first run got eight rewrites past 0.2.1. So the TrapRepo and fuzzer rows say how well the rules cover the techniques they were built against. How they do on attacks they have never seen takes a corpus they were never tuned on: the held-out test below.

## ViKernel's shell benchmark

[`bench/shellgate.py`](../bench/shellgate.py) scores the guard on the public dev split of [FINAL-Bench/Obfuscated-Shell-Gate](https://huggingface.co/datasets/FINAL-Bench/Obfuscated-Shell-Gate) (CC-BY-4.0, 222 bash commands, each risky one paired with a harmless one in the same disguise), the way the [Obfuscated-Shell Safety Leaderboard](https://huggingface.co/spaces/FINAL-Bench/obfuscated-shell-leaderboard) scores a gate: risky recall, benign pass and their mean, balanced accuracy. A deny or an ask stops a command. The leaderboard scores models on a private held-out split, so its numbers compare in method, not command for command.

The first run, on code `9b1c1484919f`, had never seen the set. The seed commands were then split in two halves by a fixed seed; the shell-unfolding change (`pah/shellfold.py`, code `12cf58a49f17`) was written by looking only at the tune half, so the test half measures it on commands it was not built against.

## Judging steps as a chain

Each attack run of the chain drill is paired with the same steps sent alone. Stopped as a chain: 77 of 77; stopped with every key step judged alone: 26 (23.4% to 45.5%). 51 runs were stopped only as a chain and 0 only alone, McNemar p = 8.9e-16. That p-value treats the runs as independent, and they are not: the 12 attack scripts each run once per agent. Counted by script, which is the independent unit, 12 of 12 are stopped in every agent they apply to; 8 are stopped only when judged as a chain and 0 only alone, McNemar p = 0.0078. That is the figure to quote.
